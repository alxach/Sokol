# Spec: Панель суперадмина — приведение к функционалу

Статус: **согласован** (2026-08-27, решения в §9)
Владелец: суперадмин системы (владелец/разработчик ЦСЕ)

## 1. Цель

Привести панель суперадмина в соответствие с реальным функционалом системы:

1. Убрать расхождения «API умеет, UI — нет» и «UI показывает не тот функционал».
2. Дать суперадмину сквозные контуры: пользователи/роли, оргструктура (регионы и центры), программы стимулирования, аудит.

## 4. Требования

### 4.1 Блок 1 — Оргструктура (Регионы и центры)

Новый раздел в «Администрировании»: **«Оргструктура»** `/admin/org`.

- **Одна страница-структура:** список регионов; по раскрытию региона — его центры; по раскрытию центра — сотрудники центра.
- **Регионы:**
  - Создание (название), переименование, удаление **пустого** региона (без центров).
  - Суперадмин не может удалить регион с центрами.
- **Центры:**
  - Создание с привязкой к региону и выбором руководителя (директора) из списка сотрудников.
  - Редактирование: название, регион, руководитель.
  - Удаление: только если у центра нет данных (спортсмены/тренеры/пользователи) — иначе soft-delete (пометить закрытым).
- **Перепривязка сотрудников:** со страницы центра можно изменить `center_id` сотрудника (дропдаун или массовый выбор).

Зависимости бэкенда: `PATCH/DELETE /organizations/regions/{id}`, `PATCH/DELETE /organizations/centers/{id}`, в `CenterCreate` — руководитель центра либо через отдельное поле/эндпоинт.

### 4.2 Блок 2 — Пользователи и роли (`/admin/users`)

- **CRUD ролей:** модальное окно или под-страница «Роли»: список ролей (код, название, системная ли несистемная), создание роли, переименование, деактивация. Системные роли (`superadmin`) нельзя деактивировать.
- **Блокировка/разблокировка из списка:** переключатель/кнопка в строке таблицы без открытия формы.
- **Приглашение:** кнопка «Пригласить» — создание пользователя и отправка пригласительного письма (или генерация одноразовой ссылки/пароля, см. открытые вопросы).
- **Сброс пароля:** действие в карточке пользователя — сгенерировать временный пароль / ссылку.
- **Устранить существующее расхождение:** при редактировании пользователя роли сейчас **заменяются одной** выбранной; требуется сохранять все роли (мультивыбор, передача полного списка в `POST /users/{id}/roles`).

Зависимости бэкенда: `POST/PATCH/DELETE /roles`, `PATCH /users/{id}` (is_active без проверки пароля), сброс пароля и invite — новые эндпоинты в auth/users-админ.

### 4.3 Блок 3 — Программы стимулирования

Новый раздел: **«Программы»** `/admin/programs` (в меню админа/суперадмина), две вкладки.

**Вкладка «Положения»** (CRUD программ):

- Список программ: название, период действия, активна/черновик, тиры (min/max gross), ставки НДФЛ и взносов.
- Создание/редактирование программы (название, ставки, признак discretionary, сроки).
- Управление тирами в карточке программы: добавление/правка/удаление диапазонов min–max.
- Деактивация программы (не физическое удаление с историями выплат).

**Вкладка «Критерии» (2026-08-28):**

- Утверждение норм `≥50К / ≥25К` по 5 критериям для любого центра (селектор слева; PUT `/incentive/criteria/{center_id}`, one запись на центр, upsert).
- Валидация «базовая ≤ полная» → 422/сообщение в форме.
- Данные видит тренер на дашборде (прогресс-бары).

Реализовано: «Положения» — CRUD для superadmin, просмотр для admin/director; у тренеров раздел недоступен («Доступ запрещён»).

Зависимости бэкенда: `POST/PATCH /incentive/programs`, `GET/PUT /incentive/criteria`. CRUD тиров (`/incentive/programs/{id}/tiers`) — пока не реализовано, тиры задаются полями min/max на программе.

### 4.4 Расхождения (спек-фиксы)

- **Меню суперадмина:** суперадмин сейчас видит модули тренера/админа. Предложение: при роли superadmin — секция «Модули» остаётся (доступ есть), но **над ней** секция «Администрирование» с полным набором: Пользователи, Роли, Оргструктура, Программы, Аудит-лог, Документы. Подтвердить на согласовании.
- **Аудит-лог:** добавить фильтры по диапазону дат и по пользователю; колонка/просмотр old/new значений действий (`old_value`/`new_value` уже приходят из API).
- **Документы** — остаётся *soon* (не в скоупе).

## 5. Вне скоупа (на потом, зафиксировано)

- Прикрутка планов мероприятий/позиций, протоколов комиссий и выплат в UI (API есть, приоритету не выбрано).
- Кнопки экспорта Excel в разделах.
- Раздел «Документы».
- Центр-scoping и владение объектами (дефер ADR-021) — отдельно.

## 7. Успешные критерии

- Суперадмин за один сеанс может: создать регион → центр → назначить руководителя → перепривязать сотрудника.
- Роли многочисленные у пользователя сохраняются при редактировании; блокировка/разблокировка из списка работают.
- Программа и её тиры создаются, правятся и деактивируются из UI.
- Аудит-лог фильтруется по датам и пользователю.
- Ни один существующий функциональный тест не сломан.

## 8. Открытые вопросы

1. Структура меню суперадмина: скрыть модульные разделы или оставить? (рекомендация: оставить, добавить сверху «Администрирование»)
2. Удаление центра при наличии данных: мягкое (закрытие) подтверждается пользователем?
3. «Приглашение»: отправлять письмо (SMTP нет в стеке) или выдавать одноразовую ссылку/пароль в UI?
4. Порядок реализации: 1) оргструктура, 2) роли/пользователи, 3) программы — подтверждается?

## 9. Решено (по умолчанию, «давай выполним» от 2026-08-27)

1. Меню: оставить модульные разделы у суперадмина, над ними — полная секция «Администрирование».
2. Центры/регионы с данными не удаляются жёстко: API даёт 409; для центра «закрытие» = `is_active=false` через PATCH.
3. Приглашение/сброс пароля без SMTP: администратору выдаётся временный пароль (показывается один раз при создании/сбросе).
4. Порядок: B1 оргструктура → B2 роли/пользователи → B3 программы → F1 меню + users → F2 оргструктура UI → F3 программы UI → F4 аудит-фильтры.
