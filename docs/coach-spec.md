## 2. Дашборд (`/`)

Блоки сверху вниз:

1. **Hero-баннер:** «Добро пожаловать!» + ФИО + сводка (спортсмены, медали, посещаемость)
2. **KPI-карточки:** «Мои спортсмены: N», «Занятий сегодня: N», «Всего медалей: N», «Ср. рейтинг: N»
3. **Критерии материального стимулирования** (Положение ред. 8) — 5 прогресс-баров:
   - Спортсмены (до 21 года): текущее / 30 чел. (≥50К) / 15 чел. (≥25К)
   - Часы тренировок: текущее / 9 ч/нед (≥50К) / 4,5 ч/нед (≥25К)
   - Мероприятия с особыми категориями: текущее / 1 в месяц
   - Спортивные мероприятия: текущее / 1 в месяц
   - Мероприятия развития: текущее / 1 в месяц
   - Цвет бара: 🟢 (≥50К), 🟡 (≥25К), 🔴 (ниже нормы)
   - Нормы (full/basic) берутся из API `/incentive/criteria` (значения по умолчанию — как в таблице; фактические утверждает руководитель центра). Пока нормы не утверждены — блок показывает заглушку «Критерии ещё не утверждены руководителем центра».
   - Источники текущих значений: спортсмены ≤21 года — из списка спортсменов тренера; мероприятия — из годового плана тренера за текущий месяц (категории 3/4/5, статусы утверждён/отправлен); часы — плановые из расписания (фактическая посещаемость — после интеграции Attendance).
4. **Мои спортсмены:** таблица с поиском и фильтрами
5. **Расписание на сегодня:** время → группа → кол-во спортсменов
6. **Планы мероприятий:** краткая сводка по кварталам

## 3. Мои спортсмены (`/athletes`)

Таблица с фильтром по `coach_id`:

- Колонки: ID, ФИО, дисциплина, разряд, возраст, статус, медали, рейтинг
- Поиск по имени, фильтры: дисциплина, статус
- **Действия:** создать, редактировать, архивировать (без удаления)
- Клик → карточка спортсмена (вкладки: информация, документы, достижения, посещаемость)

## 4. Мои группы (`/groups`) — *новый раздел*

- Список групп тренера: название, дисциплина, кол-во спортсменов, расписание
- Создать группу (название, дисциплина, описание)
- Редактировать (описание, расписание)
- Состав группы: добавить/удалить спортсмена
- Расписание группы: дни недели + время (CRUD)
- Удаление группы: ❌

## 6. Соревнования (`/competitions`)

Тренер ведёт собственный календарь соревнований: добавляет события, указывает участников и фиксирует занятые места.

### Просмотр
- Календарь разделён на «Предстоящие» и «Прошедшие» (сетка карточек)
- Каждая карточка: название, дата, город, дисциплина, уровень, кол-во участников от ЦСЕ
- Для прошедших: сводка медалей ЦСЕ (🥇🥈🥉)
- Фильтры: по статусу (все/предстоящие/прошедшие), по дисциплине
- KPI-блок: всего в календаре, участников от ЦСЕ, золотых медалей, всего медалей

### Добавление соревнования (тренер/admin)
- Кнопка «Добавить соревнование» → модалка: название, вид спорта, уровень, дата(ы), город, место
- После создания соревнование появляется в разделе «Предстоящие»

### Управление участниками
- Кнопка «Управление участниками» на карточке соревнования → модалка
- Поиск спортсмена по имени среди своих
- Добавление спортсмена в соревнование (одним кликом)
- Удаление спортсмена из соревнования

### Фиксация результатов
- Для прошедших соревнований у каждого спортсмена появляется выбор медали: 🥇 золото, 🥈 серебро, 🥉 бронза
- Медаль устанавливается/снимается кликом по кнопке
- Сводка медалей отображается на карточке соревнования

## 7. Отчёты (`/reports`)

Список с фильтрами по статусу:

| Статус | Цвет | Действия |
|--------|------|----------|
| Черновик (draft) | — | ✏️ редактировать, ➡️ отправить |
| Отправлен (submitted) | 🟡 | ожидание |
| Утверждён (approved) | 🟢 | просмотр |
| Отклонён (rejected) | 🔴 | просмотр + комментарий |

### Создание отчёта

1. Нажать «Создать отчёт» → выбрать шаблон «Основной отчёт тренера» (месячный)
2. Указать отчётный период (начало — конец месяца)
3. Заполнить 5 полей (см. критерии в [Руководстве по стимулированию](incentive-program-guide.md)):

| Поле | Тип | Форма подтверждения | Норма (50К / 25К) |
|------|-----|---------------------|-------------------|
| Кол-во занимающихся спортсменов | число | Обязательно в отчёт | ≥30 / ≥15 чел. |
| Часы тренировок в неделю | число | По запросу | ≥9 / ≥4,5 ч/нед |
| Мероприятия с особыми категориями | текст | Обязательно в отчёт | ≥1 в месяц |
| Спортивные мероприятия | текст | Обязательно в отчёт | ≥1 в месяц |
| Мероприятия развития спортсменов | текст | Обязательно в отчёт | ≥1 в месяц |

### Норм-валидация (ред. 8)

Рядом с каждым числовым полем отображается **бейдж уровня**:
- 🟢 **≥50К** — значение ≥ нормы для полного уровня выплаты
- 🟡 **≥25К** — значение ≥ нормы для базового уровня
- 🔴 **ниже нормы** — значение ниже базовой нормы

Под каждым полем отображается точная норма: «Норма: ≥30 (50К) / ≥15 (25К) чел.»

### Формы подтверждения

Каждое поле имеет тип подтверждения:
- **Обязательно в отчёт** — данные вносятся непосредственно в тело отчёта (фотоотчёт, описание)
- **По запросу** — предоставляется по требованию Благополучателя (расписание, журнал)

### Автоматический расчёт выплаты

При отправке отчёта система автоматически:
1. Сравнивает значения с нормами для каждого критерия
2. Определяет уровень выплаты:
   - Все критерии ≥ полной нормы → **50 000 ₽**
   - Все критерии ≥ базовой нормы → **25 000 ₽**
   - Хотя бы один ниже базовой → **0 ₽**
3. Сохраняет `payoutTier` в отчёте

### Расчёт брутто (Приложение №6)

В детальном просмотре отчёта (после утверждения) отображается таблица расчёта:

| Компонент | Формула | Пример (50К) |
|-----------|---------|-------------|
| Нетто (на карту) | payoutTier | 50 000 ₽ |
| НДФЛ (13%) | Брутто × 0,13 | −8 550 ₽ |
| Взносы (30,2%) | Брутто × 0,302 | 19 863 ₽ |
| Брутто (затраты Организации) | Нетто / (1 − 0,13 − 0,302) | 88 028 ₽ |

### Привязка к протоколу комиссии

Если отчёт утверждён и включён в протокол комиссии, в детальном просмотре отображается ссылка на протокол.

### Действия

- **Черновик:** [Сохранить черновик] / [Отправить на проверку]
- **Отправлен:** ожидание проверки
- **Отклонён:** исправить → отправить повторно

[Скачать Word] — экспорт отчёта в формате Word (Приложение №4)

## 9. План мероприятий (`/plans`)

Тренер создаёт один план на год с мероприятиями по трём категориям:
- Категория 3 — мероприятия с определёнными категориями населения
- Категория 4 — соревнования на территории ЦСЕ, УТС, мастер-классы
- Категория 5 — мероприятия по развитию спортсменов ЦСЕ

### Создание плана

- Кнопка «Создать план» на странице `/plans` (только если нет плана на текущий год)
- Выбор года (2025–2027, по умолчанию текущий)
- ФИО тренера и вид спорта — автоматически из профиля, read-only
- Добавление мероприятий карточками, каждая содержит: квартал, месяц, дату, категорию, название, описание, место, категорию участников, количество участников
- При выборе квартала селект месяца фильтруется — показываются только месяцы выбранного квартала. Если текущий месяц не входит в новый квартал, месяц автоматически переключается на первый в квартале
- Счётчик мероприятий по категориям

### Валидация (ред. 8)

Система проверяет ограничения Положения и отображает предупреждения:

| Правило | Описание | Отображение |
|---------|----------|-------------|
| П. 3.1.4 | Мероприятия с ≤3 участниками **не учитываются** для начисления | 🟡 Бейдж «Не учитывается (≤3, п. 3.1.4)» рядом с количеством участников |
| П. 3.1.3 | Мероприятия не из плана не могут быть оплачены (кроме спортивных) | Информационное предупреждение в детали плана |

### Импорт из Excel

- Кнопка **«Импорт Excel»** на странице `/plans`
- Поддерживаемые форматы дат: ISO (`2026-01-29`), ДД.ММ.ГГГГ (`19.02.2026`), диапазон (`4-20.02.2026`), список через запятую
- Автоматическое определение категории мероприятия по содержимому
- Preview-модалка с предупреждениями перед подтверждением импорта

### Экспорт в Excel

- Кнопка **«Excel»** в детальном просмотре плана или в списке
- Экспорт одного плана или всех отфильтрованных планов
- Формат файла соответствует образцу `Флейшман Р.В план 1-3 кв.xlsx`

### Индикатор дедлайна

В детальном просмотре плана отображается:
- 🔴 **Просрочен** — план не отправлен до начала квартала
- 🟡 **Осталось N дн.** — до дедлайна осталось ≤14 дней (план в статусе draft)

### Статусная модель

Каждое мероприятие имеет индивидуальный статус:

```
draft → submitted → approved
                 → rejected → draft (повторная отправка)
```

План агрегируется из статусов мероприятий. Общего статуса у плана нет.

### Действия

- Тренер отправляет `draft` → `submitted`
- Admin/director утверждает (`submitted` → `approved`) или отклоняет с комментарием (`submitted` → `rejected`)
- После отправки на проверку редактирование недоступно
- При отклонении admin указывает комментарий (обязательно)

### Группировка в модалке

Мероприятия группируются по кварталам (I–IV), внутри — по месяцам.

## 10. Управление отпусками (также см. раздел 11 — больничный)

### Где отображается
- **Профиль (`/profile`)** — просмотр и редактирование периодов отпуска текущего тренера
- **Карточка тренера** на странице `Тренеры` — просмотр при клике на строку

### Модель данных
Периоды отпуска хранятся как массив объектов `VacationPeriod`:
```
{ start: string (yyyy-MM-dd), end: string (yyyy-MM-dd) }[]
```

В БД — отдельная таблица `coach_vacations` (OneToMany к `coach`). На фронтенде — статические данные (`mock-data.ts`) с оверрайдами в `localStorage`.

### Как вычисляется статус
Функция `getCoachStatus(coach)`:
1. Проверяет `isOnVacation(coach.vacations)` — если сегодня попадает в любой период → `"Отпуск"`
2. Иначе возвращает `coach.status` (базовый: `"Активный"`, `"На больничном"`)

### Редактирование
- В режиме редактирования появляется кнопка «Добавить период»
- Дата выбирается через календарь (`DatePicker` из `Popover` + `Calendar`)
- Каждый период можно удалить (✕)
- После «Сохранить» данные пишутся в `localStorage` (временное решение до подключения API)
- Кнопка «Отменить» сбрасывает изменения к последнему сохранённому состоянию

### Ограничения
- Дата начала и конца обязательна для каждого периода
- Нельзя удалить все периоды через редактирование — пустой массив допустим (тренер без отпусков)
- API пока не подключён — данные синхронизируются только локально

## 11. Управление больничными

Полная аналогия с отпусками (раздел 10). Отличие — статус «На больничном» имеет приоритет над «Отпуском».

### Где отображается
- **Профиль (`/profile`)** — отдельная карточка «Больничный» со своей кнопкой ✏️
- **Карточка тренера** на странице `Тренеры`

### Как вычисляется статус
Функция `getCoachStatus(coach)`:
1. `isOnSickLeave(coach.sickLeaves)` → `"На больничном"`
2. `isOnVacation(coach.vacations)` → `"Отпуск"`
3. Иначе → `coach.status`

### Особенности
- Если `end < start`, период считается однодневным (на дату старта) — защита от опечаток
- Хранилище: `localStorage` по ключу `sokol_coach_sick_leaves`
- В БД — таблица `coach_sick_leaves` (OneToMany к `coach`)

## 13. Комиссия (`/commission`)

Раздел для просмотра протоколов заседаний комиссии по материальному стимулированию.

### Для тренера (только просмотр)

Тренер может:
- Просматривать список протоколов комиссии
- Смотреть детали: повестка, голосование, решение
- Видеть таблицу выплат (свою строку и других тренеров)
- Видеть итоговые суммы (нетто, НДФЛ, взносы, брутто)

### Структура протокола

Каждый протокол содержит:
- Номер и дата заседания
- Наименование Благополучателя
- Отчётный период
- Повестка дня
- Решения
- Голосование (за / против / воздержались)
- Таблица выплат (для каждого тренера: ФИО, вид спорта, период, нетто, НДФЛ, взносы, брутто)

### Disclaimer

Внизу страницы отображается предупреждение:
> «Выплаты по настоящему Положению осуществляются на усмотрение Организации (п. 1.3). Наличие протокола Комиссии не гарантирует выплату.»

Подробнее: [Руководство по стимулированию](incentive-program-guide.md)
