## 2. Super Admin

### 2.1 Первый вход
1. Система создаётся с seed-аккаунтом superadmin
2. Super admin меняет пароль при первом входе
3. Настраивает регионы → филиалы → роли

### 2.2 Основные сценарии

**Управление системой:**
```
Вход → Дашборд → Управление
├── Регионы:     CRUD регионов (Красноярский край, ...)
├── Филиалы:     CRUD филиалов (ЦСЕ Ачинск, ЦСЕ Шарыпово, ...)
├── Пользователи: список, создание, назначение ролей
├── Роли:        CRUD ролей, настройка прав доступа
└── Аудит:       просмотр логов действий всех пользователей
```

**Контроль:**
```
Дашборд (глобальный):
├── Количество спортсменов по филиалам
├── Количество тренеров по филиалам
├── Посещаемость средняя по системе
├── Статусы отчётов (сколько отправлено/утверждено)
├── Сравнение филиалов
└── Последние действия в системе
```

### 2.3 Flow: Создание филиала и назначение admin
```
1. Регионы → Создать регион (если нет)
2. Филиалы → Создать филиал → указать: название, регион, адрес, телефон
3. Пользователи → Создать → email, пароль, ФИО
4. Назначить роль "admin" пользователю
5. Готово — admin получает доступ к своему филиалу
```

## 3. Руководитель филиала

### 3.1 Вход в систему
```
Email + пароль → JWT → Дашборд филиала
```

### 3.2 Основные сценарии

**Дашборд филиала (главная страница):**
```
┌────────────────────────────────────────────────────┐
│ 📊 Дашборд филиала                                 │
│                                                     │
│ [Спортсменов: 150] [Тренеров: 12] [Групп: 8]       │
│ [Посещаемость: 85%] [Отчётов за неделю: 5/8 ⏳]   │
│                                                     │
│ ┌────────── График посещаемости ──────────┐        │
│ │ ████████████ 85%                        │        │
│ │ ██████████   78%     ┌─────┐            │        │
│ │ █████████████ 92%    │     │            │        │
│ │ Пн  Вт  Ср  Чт  Пт  Сб  Вс             │        │
│ └──────────────────────────────────────────┘       │
│                                                     │
│ ┌─── Топ-3 проблемных группы ─────────────────┐    │
│ │ Группа А: 60% посещаемость  → [Детали]      │    │
│ │ Группа Б: 65% посещаемость  → [Детали]      │    │
│ └──────────────────────────────────────────────┘    │
└────────────────────────────────────────────────────┘
```

**Управление тренерами:**
```
Тренеры → Список
├── Создать тренера (создаётся user + coach профиль)
├── Редактировать профиль (ставка, специализация)
├── Уволить тренера (soft-delete)
└── Статистика тренера (группы, спортсмены, посещаемость)
```

**Управление спортсменами:**
```
Спортсмены → Список (фильтры: группа, тренер, статус, разряд)
├── Создать спортсмена (ФИО, дата рождения, спорт, тренер, группа)
├── Импорт из Excel (массовая загрузка)
├── Экспорт в Excel
├── Карточка спортсмена:
│   ├── Документы (медсправка, страховка, согласия)
│   ├── Достижения (турниры, медали)
│   ├── История разрядов
│   ├── Посещаемость (график, статистика)
│   └── Перевод в другой филиал
└── Массовые операции (смена тренера, группы, статуса)
```

**Контроль отчётов:**
```
Отчёты → Список (фильтры: статус, тренер, период)
├── [5 новых] draft
├── [12] submitted ⎼⎼⎼→ Открыть → [Утвердить] [Отклонить]
├── [8] approved
└── [2] rejected
```

**Отчётность по филиалу:**
```
Отчёты → Сводка за период
├── Сколько тренеров сдали
├── Сколько утверждено
├── Просроченные отчёты
└── Сравнение с прошлым периодом
```

### 3.3 Flow: Проверка и утверждение отчёта
```
1. Входит в систему
2. Открывает раздел "Отчёты"
3. Видит список: draft → submitted → approved → rejected
4. Фильтр: "Ожидают проверки" (submitted)
5. Открывает отчёт → видит все заполненные поля
6. Принимает решение:
   ├── [Утвердить] → статус → approved, отчёт locks
   └── [Отклонить] → комментарий → статус → rejected, тренеру уведомление
7. Автоматическое уведомление тренеру
```

## 4. Тренер

### 4.1 Вход в систему
```
Email + пароль → JWT → Дашборд тренера
```

### 4.2 Основные сценарии

**Дашборд тренера:**
```
┌────────────────────────────────────────────────────┐
│ 📊 Мой дашборд                                     │
│                                                     │
│ [Спортсменов: 25] [Групп: 3] [Сегодня: 2 занятия]  │
│ [Посещаемость: 82%] [Отчёт за неделю: ⏳ черновик] │
│                                                     │
│ 📅 Расписание на сегодня:                           │
│ ├── 10:00-11:30 Группа А (12 спортсменов)          │
│ ├── 14:00-15:30 Группа Б (8 спортсменов)           │
│ └── 17:00-18:30 Группа В (5 спортсменов)           │
│                                                     │
│ 🔔 Напоминание: Отчёт за неделю не сдан!            │
└────────────────────────────────────────────────────┘
```

**Отметка посещаемости:**
```
Расписание → Выбрать занятие → Посещаемость
├── Список группы с чекбоксами:
│   ├── ☑ Иванов И. (present)
│   ├── ☐ Петров П. (absent) → причина: справка
│   ├── ☑ Сидоров С. (present)
│   └── ☐ Кузнецов К. (late) → опоздание на 10 мин
├── [Сохранить]
└── Автоматически: расчёт процента посещаемости группы
```

**Работа со спортсменами:**
```
Мои спортсмены → Список
├── Карточка спортсмена (только просмотр/редактирование)
├── Создать нового → ФИО, дата рождения, родители, телефон
├── Прикрепить к группе
├── Добавить достижение (турнир, место)
└── Загрузить документ (медсправка)
```

**Управление группами:**
```
Мои группы → Список
├── Создать группу (название, макс. вместимость)
├── Редактировать (описание, расписание)
├── Состав группы: добавить/удалить спортсмена
└── Расписание группы: настроить дни и время занятий
```

**Заполнение отчёта:**
```
Отчёты → Создать отчёт
├── Выбрать шаблон (недельный/месячный)
├── Заполнить поля:
│   ├── Количество спортсменов за период
│   ├── Проведено занятий
│   ├── Посещаемость (автоподстановка из системы)
│   ├── Выполнение плана
│   ├── Травмы/происшествия
│   ├── Работа с родителями
│   └── Примечания
├── Сохранить как черновик
└── [Отправить на проверку]
```

**Календарь:**
```
Мои мероприятия → Календарь
├── Просмотр расписания на месяц/неделю/день
├── Регистрация спортсменов на турнир
└── Заявки на сборы/выезды
```

### 4.3 Flow: Типичный день тренера
```
1. Вход → Дашборд → видит расписание на сегодня
2. Перед занятием: открывает группу → Посещаемость → отмечает
3. В течение дня: отметка посещаемости после каждого занятия
4. Конец недели:
   ├── Отчёты → Создать отчёт → заполнить → отправить
   └── Получает уведомление: "Отчёт утверждён" / "Отчёт отклонён"
5. По мере необходимости:
   ├── Добавить нового спортсмена в группу
   ├── Загрузить медсправку спортсмена
   └── Зарегистрировать на турнир
```

## 5. Методист

### 5.1 Вход в систему
```
Email + пароль → JWT → Дашборд методиста
```

### 5.2 Основные сценарии

**Управление шаблонами отчётов:**
```
Шаблоны отчётов → Список
├── Создать шаблон:
│   ├── Название: "Недельный отчёт тренера"
│   ├── Тип: weekly
│   ├── Структура (JSON):
│   │   ├── attended_planned: int     # план/факт
│   │   ├── injuries: text            # травмы
│   │   ├── notes: text               # примечания
│   │   └── ...
│   └── [Сохранить]
├── Редактировать шаблон
└── Архивировать (деактивировать)
```

**Аналитика качества:**
```
Аналитика → Отчёты
├── Процент тренеров, сдавших вовремя
├── Качество заполнения (полнота данных)
├── Часто используемые шаблоны
└── Предложения по улучшению шаблонов
```

**Flow: Создание нового шаблона отчёта:**
```
1. Методист анализирует текущие отчёты
2. Определяет, какие поля нужны
3. Заходит в "Шаблоны отчётов" → "Создать"
4. Заполняет: название, тип (weekly/monthly/quarterly)
5. Конфигурирует JSON-схему полей
6. Активирует шаблон
7. Шаблон становится доступен тренерам при создании отчёта
```

## 6. Сквозные сценарии

### 6.1 Регистрация пользователя

```
┌──────────┐    ┌───────────────┐    ┌──────────┐
│ Приглашение│    │ Саморегистрация│    │  Админ   │
│  по email │    │               │    │ создаёт  │
└─────┬─────┘    └──────┬────────┘    └─────┬────┘
      │                 │                   │
      └─────────────────┼───────────────────┘
                        │
                        ▼
              ┌──────────────────┐
              │  Заполняет:      │
              │  email, пароль,  │
              │  ФИО, телефон    │
              └────────┬─────────┘
                       │
                       ▼
              ┌──────────────────┐
              │ Подтверждение    │
              │ email            │
              └────────┬─────────┘
                       │
                       ▼
              ┌──────────────────┐
              │ Назначение роли  │
              │ (админом)        │
              └────────┬─────────┘
                       │
                       ▼
              ┌──────────────────┐
              │ Первый вход      │
              │ → Дашборд        │
              │ под своей ролью  │
              └──────────────────┘
```

### 6.2 Жизненный цикл отчёта

```
Черновик (draft)
    │
    ▼ автор → [Отправить]
Отправлен (submitted)
    │
    ▼ руководитель → [Проверить]
    ├── ✅ Утвердить → Утверждён (approved)
    └── ❌ Отклонить → Отклонён (rejected)
                           │
                           ▼ автор → [Исправить]
                      Черновик → ... повторный цикл
```

### 6.3 Жизненный цикл документа

```
Черновик (draft)
    │
    ▼ автор → [Отправить на согласование]
На согласовании (pending_approval)
    │
    ▼ согласующий
    ├── ✅ Согласовать → Согласован (approved)
    └── ❌ Отклонить → Отклонён (rejected)
                           │
                           ▼ автор → [Доработать]
                      Черновик → ... повторный цикл
```

### 6.4 Посещаемость: полный цикл

```
1. Тренер создаёт группу
2. Назначает расписание (дни недели, время)
3. Добавляет спортсменов в группу
4. После каждого занятия → отметка посещаемости
5. Система считает статистику:
   - Средняя посещаемость группы
   - Посещаемость каждого спортсмена
   - Динамика за месяц
6. Руководитель видит агрегированную статистику
7. Данные посещаемости подтягиваются в отчёты
```

### 6.5 Импорт спортсменов из Excel

```
1. Админ/тренер → Спортсмены → Импорт
2. Выбирает Excel-файл
3. Система валидирует:
   - Обязательные поля (ФИО, дата рождения)
   - Формат данных
   - Дубликаты (по email, телефону)
4. Показывает предпросмотр с ошибками (если есть)
5. Подтверждение импорта
6. Система создаёт спортсменов
7. Результат: "Создано 45, ошибок 2, дубликатов 3"
```
