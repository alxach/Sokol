## 2. Дашборд (`/`)

Блоки сверху вниз:

1. **KPI-карточки:** «Спортсменов: N», «Тренеров: N», «Групп: N», «Посещаемость: N%», «Отчётов за неделю: N/M ⏳»
2. **Дедлайны планов:** тренеры, не отправившие планы до начала квартала (🔴 просрочены) или с дедлайном ≤14 дней (🟡)
3. **График посещаемости:** по дням недели (bar chart)
4. **Топ проблемных групп:** 3 группы с низкой посещаемостью → [Детали]
5. **Сводка по отчётам:** сколько черновиков, отправлено, утверждено, отклонено
6. **Сводка по комиссии:** кол-во протоколов за текущий месяц, общая сумма утверждённых выплат
7. **Последние действия:** активность всех пользователей центра (аудит)

## 3. Спортсмены (`/athletes`)

Полный CRUD всех спортсменов центра:

- Таблица: ID, ФИО, дисциплина, разряд, возраст, город, тренер, статус, медали, рейтинг
- Поиск + фильтры: группа, тренер, статус, разряд
- **Создать** спортсмена (ФИО, дата рождения, спорт, тренер, группа)
- **Редактировать** карточку
- **Удалить** (permanent или archive)
- **Импорт** из Excel (массовая загрузка)
- **Экспорт** в Excel
- **Массовые операции:** смена тренера, группы, статуса
- Клик → карточка спортсмена:
  - Информация
  - Документы (медсправка, страховка, согласия)
  - Достижения (турниры, медали)
  - История разрядов
  - Посещаемость (график, статистика)
  - Перевод в другой центр

---

## 4. Тренеры (`/coaches`)

CRUD тренеров своего центра:

- Таблица: ФИО, дисциплины, групп, спортсменов, нагрузка, рейтинг, эффективность, статус
- **Создать** тренера (создаётся user + coach профиль)
- **Редактировать** профиль (ставка, специализация)
- **Уволить** (soft-delete)
- **Статистика** тренера: группы, спортсмены, посещаемость, отчёты

---

## 5. Группы (`/groups`)

CRUD всех групп центра:

- Таблица: название, дисциплина, тренер, кол-во спортсменов, макс. вместимость, расписание
- **Создать** группу
- **Редактировать**
- **Удалить**
- **Назначить тренера**
- Состав группы: добавить/удалить спортсмена
- **Передать** группу другому тренеру

---

## 6. Расписание (`/schedule`)

Полный CRUD расписания центра:

- Календарь (месяц/неделя/день)
- Фильтры: группа, тренер, день недели
- **Создать** занятие (группа, время, место, тренер)
- **Редактировать / удалить**

---

## 7. Посещаемость (`/attendance`)

Просмотр по всему центру:

- Сводка: средняя посещаемость по центру
- Таблица: группа → тренер → % посещаемости → динамика
- Heatmap по дням недели
- Детализация: клик на группу → журнал посещаемости
- **Не может отмечать** (только coach)

## 8. Соревнования / Мероприятия (`/competitions`, `/events`)

Полный CRUD:

- **Создать** соревнование / мероприятие
- **Редактировать, отменить**
- Календарь
- Просмотр заявок от тренеров
- Протоколы, результаты

## 9. Отчёты (`/reports`)

Просмотр всех отчётов центра + утверждение:

- Сводка: сколько сдано, утверждено, просрочено
- Список с фильтрами: статус, тренер, период
- **Статусы:** draft → submitted → approved / rejected
- **Действия:**
  - submitted → [Утвердить] / [Отклонить + комментарий]
  - После утверждения — отчёт lock

### Проверка отчёта (ред. 8)

При открытии отчёта тренера руководитель видит:
- **Норм-валидацию** — бейджи ≥50К / ≥25К / «ниже нормы» для каждого критерия
- **Форму подтверждения** — обязательная / по запросу (с цветовой индикацией)
- **Расчёт выплаты** — автоматически рассчитанный уровень (50К / 25К / 0)
- **Таблицу расчёта брутто** — нетто → НДФЛ → взносы → брутто

### Утверждение с расчётом выплаты

При утверждении отчёта:
1. Система фиксирует `payoutTier` (50 000 или 25 000 ₽)
2. Отчёт привязывается к текущему `programId` (программа стимулирования)
3. При необходимости — привязка к протоколу комиссии (`commissionProtocolId`)

### Сравнение с прошлым периодом

Доступно сравнение показателей отчёта с предыдущим периодом.

## 12. Протоколы комиссии (`/commission`)

Заседания комиссии по материальному стимулированию тренеров (Приложение №6 Положения).

### Создание протокола

1. Нажать «Новый протокол»
2. Заполнить:
   - Номер протокола (формат: ПСМС-ГГГГ-ННН)
   - Дата заседания
   - Наименование Благополучателя
   - Отчётный период
   - Повестка дня
   - Решения
3. Голосование: за / против / воздержались
4. Добавить строки выплат (для каждого тренера):
   - ФИО, вид спорта, период
   - Сумма нетто (автоматически из отчёта)
   - Система автоматически рассчитает НДФЛ и взносы

### Валидация

Система проверяет:
- **П. 3.2.3:** Доля спортивных мероприятий ≤ 5% от бюджета ЦСЕ (предупреждение)
- **П. 4.3:** Доля спортивных мероприятий ≤ 30% от общего бюджета (блокировка)

### Просмотр

- Список всех протоколов с фильтрацией по периоду и статусу
- Детализация: повестка, голосование, таблица выплат
- Итоговые суммы: нетто, НДФЛ, взносы, брутто

### Статусная модель

```
draft → approved → rejected
```

### Действия

- **Черновик:** редактирование, удаление
- **Утвердить:** фиксация протокола, привязка к отчётам тренеров
- **Отклонить:** с комментарием

Подробнее: [Руководство по стимулированию](incentive-program-guide.md)

## 13. Программы стимулирования

Просмотр активных программ материального стимулирования.

### Информация о программе

- Наименование, номер приказа, дата, редакция
- Размер выплат: макс. / мин.
- Ставки НДФЛ и страховых взносов
- Статус: активна / архивирована
- Факультативность выплат (п. 1.3)

### Действия (только просмотр)

Rucоводитель центра **не управляет** программами — это прерогатива руководителя всех центров. Доступен только просмотр параметров текущей программы.

## 12. Управление (footer)

### Пользователи (`/users`)

CRUD учётных записей в своём центре:

- Список пользователей центра
- **Создать** учётку (email, пароль, ФИО)
- Назначить роль: `coach`, `methodist`, `viewer`
- Заблокировать / разблокировать
- **Не может** создавать `admin` или `superadmin`

### Центр (`/center`)

Редактирование своего центра:

- Название, адрес, телефон
- Регион

### Аудит (`/audit`)

Просмотр логов действий в центре:

- Кто, когда, что сделал
- Фильтры: пользователь, действие, дата

---

## 13. Профиль (`/profile`)

- Аватар
- ФИО, телефон, email
- Центр (просмотр)

## 15. Ограничения admin

- Не выходит за пределы своего центра
- Не управляет ролями и правами
- Не создаёт пользователей с ролью `admin` или `superadmin`
- Не видит данные других центров
- Не удаляет центр
