# ADR-023: Явное назначение тиров тренеров и выплата по тиру

## Status
Accepted

## Date
2026-08-30

## Context

По Положению ред. 8 (Приложение №6) тренер получает **полную** (максимум активной программы) или **базовую** (минимум программы) выплату. До сих пор:

- Норма и сумма определялись **автоматически по факту** выполнения норм отчёта: все `normFull` → 50 000 ₽, иначе все `normBasic` → 25 000 ₽.
- Не было механизма, которым руководитель центра явно решает, на каком уровне стимулируется конкретный тренер. Ред. 8 подразумевает решение Организации (п. 1.3), а не гонку «набрал-ненабрал» нормы.
- `coach-spec.md` и UI-бейджи «≥50К / ≥25К» вводили в заблуждение: можно было дойти до полной нормы, но не «узнать» о полной выплате.

## Decision

### 1. Колонка `coaches.incentive_tier`

Таблица `coaches` дополнена строкой:

- `incentive_tier VARCHAR(10) NULL` — `"full"` или `"basic"`.
- `NULL` = тир ещё не назначен руководителем → тренеру показывается заглушка «выплата не назначена», отчёт передаёт `payout_tier = 0`.

Миграция `e0f1a2b3c4d5_add_coach_incentive_tier` (revises `d5e6f7a8b9c0`).

### 2. API

| Method | Endpoint | Роли | Семантика |
|--------|----------|------|-----------|
| GET | `/incentive/coach-tiers?center_id=` | admin (свой центр), director, superadmin | Список тренеров центра с текущим тиром (`CoachTierOut`) |
| PUT | `/incentive/coach-tiers/{coach_id}` | admin (свой центр), director, superadmin | Назначить/изменить тир (`CoachTierUpdate: {tier: "full"|"basic"}` → 422) |

- `GET /incentive/criteria` дополнен **виртуальным** полем `assigned_tier` (из `coaches.incentive_tier` тренера текущего пользователя) — тренер узнаёт свой тир без отдельного запроса.
- Ошибки: coach → 403; admin без центра / чужой центр → 403; неизвестный coach → 404; невалидный `tier` → 422.

### 3. Расчёт выплаты — `report_service._compute_payout(report)`

Логика изменила **источник истины норм**: раньше «все full → max», теперь по назначенному тиру:

- тир `full` → выполняются все `normFull` → `max_payout` активной программы;
- тир `basic` → выполняются все `normBasic` → `min_payout` активной программы;
- без тира — выплата `0`, независимо от выполненной нормы;
- тренер с тиром `basic`, выполнивший полные нормы, всё равно получает `min_payout` (выплата определяется назначенным тиром, а не достигнутыми нормами).

Бейджи «≥50К / ≥25К» в `ReportDetailModal` оставлены как справочные по норме шаблона, но фактическая сумма и статус «ниже нормы» показываются по нормам назначенного тира.

### 4. UI

- `admin/programs.tsx` (вкладка «Критерии») — карточка «Назначение выплат тренерам»: таблица тренеров центра, RadioGroup «Полный/Базовый», кнопка «Сохранить» активна при изменении; бейдж «не назначено» для тренеров без тира.
- Дашборд тренера (`routes/index.tsx`) — блок «Критерии материального стимулирования»: нормы `*_full`/`*_basic` в зависимости от `assigned_tier`, бейдж «Полная выплата <max>» / «Базовая выплата <min>» из активной программы, без тира — заглушка «обратитесь к руководителю центра».
- Форма отчёта (`reports/new.tsx`) — зелёный баннер «Тир выплаты: полный/базовый» или янтарный «выплата не назначена, сумма 0 ₽».
- Детали отчёта (`reports.tsx`) — предупреждение «Выплата не сформирована (0 ₽)» для не-черновиков; сумма бейджа расчёта берётся из `payout_tier`, а не захардкожена (50К/25К).

## Consequences

- **Положительные:** выплата — явное кадровое решение, а не побочный результат заполнения отчёта; тренер с первой минуты знает целевой уровень; сервер — единственный источник правды по сумме.
- **Отрицательные:** до назначения тира все отчёты тренера дают 0 ₽ — руководитель обязан назначить тир (иначе комиссия не начислит выплату). Временно нет «авторасчёта по факту», если руководитель не отметил тир.

## Deferred

- Управление тирами в отдельном месте (кроме вкладки «Программы»), например на странице тренера.
