# ADR-007: routerState.matches.length включает __root__

## Status
Accepted

## Date
2026-06-20

## Context
При реализации дочернего роута `/plans/new` внутри родительского `/plans` потребовалось определить, активен ли дочерний роут, чтобы родительский компонент (`PlansPage`) рендерил либо список планов (на `/plans`), либо пустой `<Outlet/>` (на `/plans/new`).

Первая версия проверки:

```typescript
const isChildRoute = routerState.matches.length > 1;
```

Это привело к тому, что страница `/plans` перестала рендерить контент — браузер получал пустой HTML.

## Root Cause
В TanStack Router `routerState.matches` — это массив **всех** совпавших роутов в иерархии, включая `__root__`.

Для `/plans` массив содержит:
```
[__root__, /plans]  → length = 2
```

Для `/plans/new`:
```
[__root__, /plans, /plans/new]  → length = 3
```

Условие `length > 1` срабатывало **для любого роута**, потому что `__root__` всегда первый в массиве. Любая страница (кроме самого `__root__`) имеет минимум 2 элемента — следовательно, `length > 1` всегда истинно.

## Decision
Использовать `> 2` вместо `> 1`:

```typescript
const isChildRoute = routerState.matches.length > 2;
```

- Для `/plans`: `length = 2 → 2 > 2 = false` → рендерится список
- Для `/plans/new`: `length = 3 → 3 > 2 = true` → рендерится `<Outlet/>`

## Alternatives Considered
- **Проверка `routerState.location.pathname`**: надёжнее для конкретных путей, но ломается при добавлении новых дочерних роутов
- **`useMatches()` и сравнение routeId последнего и предпоследнего элемента**: избыточно для текущей глубины вложенности
- **Реструктуризация роутов (layout-компонент + plans/index.tsx)**: правильный архитектурный подход, но требует больше изменений

## Consequences
- Проверка `> 2` корректно работает для текущей схемы роутинга (корень → роут → дочерний роут)
- Если появится третий уровень вложенности (child of child), условие останется верным (`length = 4 > 2`)
- Если появится layout-роут между `__root__` и `/plans`, условие сломается и потребует пересчёта
- Для layout-роутов правильным решением будет выделить компонент-обёртку с `<Outlet/>` и не использовать `isChildRoute`
