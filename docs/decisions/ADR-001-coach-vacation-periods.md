# ADR-001: Multiple Vacation Periods per Coach

## Status
Accepted

## Date
2026-06-18

## Context
Тренерам нужно указывать несколько периодов отпуска в году (например, летний и зимний). Ранее модель `Coach` содержала два поля — `vacation_start` и `vacation_end` — что допускало только один период.

Требования:
- Тренер может иметь 0..N отпусков в году
- Статус тренера вычисляется автоматически: если текущая дата попадает в любой период → «Отпуск», иначе используется базовый статус
- Периоды отпуска редактируются на странице профиля и в карточке тренера
- Данные должны сохраняться между сессиями (пока локально, через API позже)

## Decision

### Backend: отдельная таблица `coach_vacations`
Создана модель `CoachVacation` со связью `OneToMany` к `Coach`. Это позволяет хранить N периодов без изменения схемы `coaches`.

```python
class CoachVacation(Base):
    __tablename__ = "coach_vacations"
    id: Mapped[int] = mapped_column(primary_key=True)
    coach_id: Mapped[int] = mapped_column(ForeignKey("coaches.id", ondelete="CASCADE"))
    start_date: Mapped[date]
    end_date: Mapped[date]
```

### Frontend: массив `VacationPeriod[]` вместо пары полей
Тип `Coach.vacations` — опциональный массив `{ start: string; end: string }`.

Статус вычисляется функцией `getCoachStatus()`:
1. Вызов `isOnVacation(vacations)` — проверяет все периоды
2. Если ни один не покрывает сегодня → возвращается `coach.status`

Механизм хранения:
- Пока данные живут в `mock-data.ts` (статические) + `localStorage` (оверрайды через `sokol_coach_vacations`)
- Оверрайды полностью заменяют массив для конкретного coach_id (не мержатся)

### DatePicker
Использован `react-day-picker` v9 через штатные компоненты shadcn/ui (`Popover` + `Calendar`). Дата выбирается календарём, а не текстовым вводом (лучший UX).

## Alternatives Considered

### JSON-поле в `coaches`
- Плюсы: не нужно создавать отдельную таблицу
- Минусы: нет внешних ключей, сложнее запросы (например, «кто в отпуске в июле?»), нет типов в БД
- **Rejected**: OneToMany правильнее с точки зрения нормализации

### Хранение одной строкой (csv дат)
- Плюсы: минимальные изменения схемы
- Минусы: парсинг строк, валидация, невозможность запросов
- **Rejected**: анти-паттерн

### Мерж оверрайдов с мок-данными
- Плюсы: сохраняет оригинальные данные, добавляя изменения
- Минусы: сложность реализации, неясное поведение при удалении
- **Rejected**: полная замена массива проще и предсказуемее

## Consequences
- Миграция удалила `vacation_start/end` из `coaches`, создала `coach_vacations`
- Фронтенд синхронизирует состояние через `useEffect` при смене `coachProfile`
- При подключении реального API оверрайды из localStorage можно будет мигрировать
- `name` в auth mock приведён в соответствие с `mock-data.ts` (полное ФИО вместо инициалов)
