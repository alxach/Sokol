# ADR-008: Модуль «Соревнования» (Competitions)

## Status
Updated (2026-06-28)

## Date
2026-06-20

## Context

В системе «СОКОЛ» требуется модуль для учёта соревнований и турниров: тренер ведёт собственный календарь, отмечает участие своих спортсменов и фиксирует занятые места.

На текущий момент:
- **Бэкенд** — модель `Event → Competition → Participant → Result`, CRUD API на `/events`
- **Фронтенд** — страница `/competitions` на моках с плоской моделью `Competition`
- **coach-spec.md** — раздел 6 пустой

Требования (v2):
- Тренер добавляет соревнования в свой календарь
- Тренер включает своих спортсменов для участия
- Тренер указывает результаты своих спортсменов (5 категорий: 1 место / 2 место / 3 место / 5-6 место / Без места)
- Фильтрация по статусу (предстоящие/прошедшие/отменённые) и по результатам (с результатом/без результата)
- **Тренер может редактировать детали своих соревнований**
- **Тренер может отменять или удалять свои соревнования (с подтверждением)**
- **Admin может просматривать календарь всех тренеров центра**
- **localStorage persistence для мок-фазы** (счётчик ID + массив competitions)
- **На дашборде тренера — карточка «Мои соревнования»** (фильтр по coachId)
- **Отменённые соревнования — бейдж + секция + полупрозрачная карточка**
- Экспорт в Excel

## Decision

### Бизнес-логика

1. **Кто создаёт:** тренер (свои соревнования), admin/director (любые)
2. **Кто добавляет спортсменов:** тренер (только своих)
3. **Кто указывает места:** тренер (для своих спортсменов)
4. **Кто просматривает:** тренер — только свои; admin/director — все соревнования центра

Соревнование — плоская запись (без разделения на Event → Competition). Тренер создаёт одно событие, указывает дисциплину, уровень, даты, город, список своих спортсменов с результатами.

Дополнительные операции (v2):
- **Редактирование:** тренер может изменить название, даты, город, дисциплину, уровень, место проведения
- **Отмена:** устанавливает статус `cancelled`, карточка становится полупрозрачной с бейджем «Отменено»
- **Удаление:** после подтверждения (`confirm()`) запись удаляется

### Модель данных

Бэкенд (адаптация существующей модели):

```
Competition:
  id                uuid PK
  coach_id          uuid FK → coaches.id
  center_id         uuid FK → centers.id
  discipline        varchar(100)
  level             varchar(50)   — "муниципальный" | "региональный" | "федеральный" | "международный"
  title             varchar(300)
  date              date
  date_end          date?
  city              varchar(200)
  location          varchar(300)?
  description       text?
  status            varchar(20)   — "upcoming" | "past" | "cancelled"
  created_at        timestamptz
  updated_at        timestamptz

CompetitionAthlete:
  id                uuid PK
  competition_id    uuid FK → competitions.id (ON DELETE CASCADE)
  athlete_id        uuid FK → athletes.id
  medal             varchar(20)?  — "gold" | "silver" | "bronze" | null
  notes             text?
```

Связи:
- `Competition` N:1 → `Coach`
- `Competition` N:1 → `Center`
- `CompetitionAthlete` N:1 → `Competition` (cascade delete)
- `CompetitionAthlete` N:1 → `Athlete`

### Фронтенд: модель

```typescript
interface Competition {
  id: string;
  coachId: string;
  coachName?: string;
  title: string;
  discipline: Discipline;
  level: EventLevel;
  date: string;
  dateEnd?: string;
  city: string;
  status: "upcoming" | "past" | "cancelled";
  athletes: CompetitionAthlete[];
}

type CompetitionResult = "1 место" | "2 место" | "3 место" | "5-6 место" | "Без места";

interface CompetitionAthlete {
  athleteId: string;
  athleteName: string;
  result?: CompetitionResult;
}
```

### API спецификация (REST)

| Метод | Endpoint | Роль | Описание |
|-------|----------|------|----------|
| GET | `/api/v1/competitions` | coach, admin, director | Список соревнований (coach → только свои; admin → свой центр; director → по `?center_id=`) |
| GET | `/api/v1/competitions/:id` | все | Детали соревнования со спортсменами |
| POST | `/api/v1/competitions` | coach, admin | Создать соревнование |
| PATCH | `/api/v1/competitions/:id` | coach, admin | Обновить (пока статус не cancelled) |
| DELETE | `/api/v1/competitions/:id` | coach (свои), admin | Удалить |
| POST | `/api/v1/competitions/:id/athletes` | coach | Добавить спортсмена (с указанием медали или без) |
| DELETE | `/api/v1/competitions/:id/athletes/:athleteId` | coach | Удалить спортсмена из соревнования |
| PATCH | `/api/v1/competitions/:id/cancel` | coach | Отменить соревнование (status → `cancelled`) |

### UX/UI тренера

**Календарь (`/competitions`):**
- Сетка карточек, разделённая на «Предстоящие», «Прошедшие» и «Отменённые»
- Каждая карточка: название, дата, город, дисциплина, уровень
- Для прошедших: сводка медалей ЦСЕ (🥇🥈🥉)
- Для отменённых: бейдж «Отменено» + полупрозрачная карточка (opacity-60)
- Фильтры: статус (Все / Предстоящие / Прошедшие / Отменённые), по результатам (Все / С результатом / Без результата)
- KPI-блок: всего в календаре, участников от ЦСЕ, медалей

**Добавление соревнования:**
- Кнопка «Добавить соревнование» → форма: название, уровень, дисциплина, дата(ы), город, место
- После создания — карточка с кнопкой «Участники» для добавления спортсменов

**Редактирование соревнования:**
- Кнопка «Редактировать» на карточке → та же форма (CompetitionFormModal) с предзаполненными полями
- Сохраняет изменения через `handleUpdate`

**Удаление/отмена соревнования:**
- Кнопка «Удалить» на карточке → `confirm()` → удаление из массива + persistence
- Кнопка «Отменить» (для предстоящих) → `confirm()` → статус → `cancelled`
- После отмены карточка: opacity-60 + бейдж «Отменено»

**Добавление спортсмена:**
- В карточке соревнования кнопка «Участники»
- Выбор из своих спортсменов (с поиском)
- Опционально: указать медаль (золото/серебро/бронза)
- Возможно добавить нескольких спортсменов

**Редактирование результатов:**
- В прошедшем соревновании у каждого спортсмена можно указать/изменить результат
- Результат — выбор из 5 категорий: «1 место», «2 место», «3 место», «5-6 место», «Без места» (сброс при повторном клике)
- «Без места» — участник без призового результата, не учитывается в KPI «Всего с местами»

### UX/UI admin

- Видит соревнования всех тренеров своего центра
- Фильтр по тренеру
- Кнопки: «Excel», может удалять соревнования
- Редактирование/удаление — те же права, что у тренера

### Дашборд тренера

- Карточка «Мои соревнования» в `/`:
  - Фильтр `competitions.coachId === user.id`
  - Показывает до 5 предстоящих соревнований
  - Для каждого: название, город, дата, уровень

### Доработки бэкенда

- Создать модель `Competition` + `CompetitionAthlete` (отдельно от существующей Event → Competition)
- Добавить эндпоинты в новый роутер `/api/v1/competitions`
- Исключить проверку уровня доступа coach для событий других тренеров
- **Выпадающий список «Вид спорта»** в форме создания/редактирования соревнования должен по умолчанию подставлять дисциплину тренера (`user.coachDiscipline`). На моках реализовано через проп `defaultDiscipline`. При переходе на бэкенд — передавать `coachDiscipline` из профиля пользователя (поле `users.discipline` или `coaches.discipline`). Для admin/director — показывать пустой выбор или первую дисциплину из списка.

## Alternatives Considered

1. **Использовать существующую модель Event → Competition** — rejected. Она спроектирована для admin-сценариев (группа соревнований внутри одного события). Для тренера нужна плоская модель «одно соревнование = одна запись».
2. **Результаты вводит admin** — rejected на основе новых требований. Тренер сам ведёт учёт.
3. **Спортсмены добавляются через регистрацию (request/confirm)** — rejected. Избыточно для внутреннего учёта ЦСЕ.

## Notes (v3 — система результатов)

- Тип `CompetitionResult`: `"1 место" | "2 место" | "3 место" | "5-6 место" | "Без места"`
- `resultOrder: CompetitionResult[]` — порядок отображения кнопок в модалке
- `CompetitionAthlete.result?: CompetitionResult` — заменило `medal?: "gold" | "silver" | "bronze"`
- Кнопки результатов: при повторном клике на тот же результат — сброс (`undefined`)
- KPI «Победителей (1 место)» — количество спортсменов с `result === "1 место"`
- KPI «Всего с местами» — количество спортсменов с `result` не равным `undefined` и не равным `"Без места"`
- «Без места» = спортсмен участвовал, но не занял призовое место — учитывается в общем числе участников, но не в «Всего с местами»
- `ResultBadge` — компактный бейдж с текстом категории и количеством
- `Athlete.medals: { gold, silver, bronze }` — глобальная статистика спортсмена — **не меняется** (остаётся gold/silver/bronze для профиля спортсмена)
- `Medal` импорт из lucide-react оставлен для иконки в KPI (не удалять)

## Notes (v4 — фильтр по результатам)

- Убран фильтр дисциплин (для coach'а соревнования и так фильтруются по coachId, для admin видно все)
- Добавлен фильтр по результатам: «Все» / «С результатом» / «Без результата»
- «С результатом» — хотя бы у одного участника проставлен result (не «Без места»)
- «Без результата» — ни у одного участника нет result с призовым местом (включает пустые соревнования и те, где все «Без места»)
- `resultFilter` state: `"all" | "with_result" | "without_result"`
- Логика в `filtered` useMemo, проверка по `c.athletes.some()`
