# ADR-013: Coach Groups (Мои группы)

## Status
Accepted

## Date
2026-06-28

## Context

Модуль «Мои группы» (`/groups`) — управление учебными группами тренера. Спортсмен объединяется в группы по дисциплине и уровню подготовки. Расписание привязано к группе.

На текущий момент:

- **Типы:** `Group { id, name, discipline, coachId, coachName, athleteIds, description }`, `Athlete { ..., groupId? }`
- **Связь:** двунаправленная — `Athlete.groupId` ссылается на `Group.id`, `Group.athleteIds` содержит массив `Athlete.id`
- **Фронтенд:** страница `/groups` на моках, создание группы с выбором состава, просмотр деталей
- **coach-spec.md** — раздел 4 описывает требования

Требования:

- Тренер создаёт, редактирует, просматривает свои группы
- Тренер добавляет спортсмена в группу: либо из числа уже добавленных в систему (без группы), либо создавая нового
- Тренер удаляет спортсмена из группы
- Спортсмен может быть только в одной группе
- Admin/director видят все группы своего центра (read-only)
- Удаление группы — только admin

## Decision

### Ролевая модель

| Роль | Создание | Редактирование | Добавление в состав | Удаление из состава | Удаление группы |
|------|----------|----------------|---------------------|---------------------|-----------------|
| Coach | ✅ | ✅ | ✅ | ✅ | ❌ |
| Admin | ❌ (в мок-фазе) | ❌ | ❌ | ❌ | ✅ |
| Director | ❌ | ❌ | ❌ | ❌ | ❌ |

### Связь Athlete ↔ Group

- Единый источник истины в мок-фазе — `Group.athleteIds`
- `Athlete.groupId` — производное поле, синхронизируется через `syncGroup()`:
  - При добавлении спортсмена в группу: `athlete.groupId = group.id`, `group.athleteIds.push(athlete.id)`
  - При удалении из группы: `athlete.groupId = undefined`, `group.athleteIds = group.athleteIds.filter(id !== athlete.id)`
  - При создании спортсмена в контексте группы: обе ссылки проставляются сразу
- Спортсмен может быть только в одной группе

### UX/UI тренера

**Создание группы (боковая панель):**
- Поля: название, вид спорта (авто, readonly), описание (textarea)
- **Состав:** чекбоксы спортсменов тренера
  - Спортсмены **без группы** — активные чекбоксы
  - Спортсмены **из других групп** — disabled чекбоксы + подпись «В группе: Название»
- Кнопка «+ Новый» → QuickAthleteModal (создание нового спортсмена)
- Созданная группа сразу выбирается в деталях

**Деталь группы (боковая панель):**
- Шапка: название + кнопка редактирования (карандаш)
- Описание, дисциплина
- Расписание: дни/время/зал (просмотр)
- **Состав:**
  - Список спортсменов: аватар, имя, разряд
  - Кнопка `✕` у каждого спортсмена для удаления из группы (только для тренера)
  - Кнопка «+ Добавить» → модалка добавления

**Модалка добавления спортсмена в группу:**
- Две вкладки:
  1. **«Из спортсменов»** — список спортсменов тренера **без группы**
     - Поиск по фамилии (фильтрация)
     - Клик по строке → добавляет в группу, модалка закрывается
  2. **«Новый»** — QuickAthleteModal (создание нового спортсмена в эту группу)
- Если нет свободных спортсменов — сообщение «Все спортсмены уже распределены по группам»

**Редактирование группы:**
- Открывает ту же форму что и создание, но с предзаполненными данными
- Название, описание — редактируются
- Вид спорта — readonly
- Состав — те же правила: занятые disabled, свободные доступны

**Удаление спортсмена из группы:**
- Кнопка `✕` в строке спортсмена в составе
- Подтверждение не требуется (быстрое действие)
- При удалении: `athlete.groupId = undefined`, `group.athleteIds` очищается

### Модель данных (мок-фаза)

```typescript
interface Group {
  id: string;              // "GRP-001"
  name: string;            // "Начальная подготовка"
  discipline: Discipline;
  coachId: string;
  coachName: string;
  athleteIds: string[];    // ["SK-0421"]
  description?: string;
}

interface Athlete {
  // ... существующие поля
  groupId?: string;        // ссылка на Group.id
}
```

## Alternatives Considered

1. **Трёхшаговый мастер: выбор спортсменов → создание → результат** — rejected. Тренеру нужно быстро добавлять спортсменов, две вкладки покрывают оба сценария без лишних шагов.
2. **Одна модалка со списком всех + кнопка «Создать нового»** — rejected. Смешивание двух разных действий (выбор из существующих vs создание нового) в одном списке хуже по UX.
3. **Автоматическое создание группы при добавлении спортсмена** — rejected. Группа — самостоятельная сущность с расписанием, должна создаваться осознанно.

## Consequences

- Доработать `frontend/src/routes/groups.tsx`:
  - Модалка выбора спортсмена (две вкладки)
  - Пометка занятых спортсменов при создании/редактировании
  - Кнопка удаления из состава
  - Редактирование группы (форма с предзаполнением)
- Доработать `frontend/src/routes/athletes.tsx` — показывать название группы спортсмена
- coach-spec.md — раздел 4 актуален

## Notes

- Расписание группы (CRUD) — вынесено в отдельную задачу, сейчас только просмотр через связь с `schedules`
- Удаление группы — запланировано для admin (в мок-фазе не реализовано)
- При миграции на бэкенд: `Group` → таблица `groups`, `Athlete.groupId` → `athlete.group_id` FK
