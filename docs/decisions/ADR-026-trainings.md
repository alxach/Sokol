# ADR-026: Модуль «Тренировки с сотрудниками РУСАЛа»

## Status
Accepted

## Date
2026-09-02

## Context

ЦСЕ регулярно проводит ознакомительные тренировки с сотрудниками РУСАЛа. До сих пор такие мероприятия нигде не фиксировались: их приходилось вручную вносить и в годовой план тренера (пункт категории 4 «Спортивные мероприятия на развитие ЦСЕ»), и в ежемесячный отчёт (п. 4 `sport_events`). Это приводило к дублированию данных и пропускам.

Требовалось:

- Руководитель/админ центра предлагает **слоты** (дата, время, локация), тренеры выбирают удобные.
- Тренер, записавшись, указывает **цель**; количество участников он ставит **по факту явки** уже после тренировки (заранее не известно). Этих данных достаточно, чтобы **автоматически** создать пункт годового плана и подставить значение в отчёт.
- Нельзя смоделировать как обычную тренировку: у события фиксированное название, привязка к плану и отчёту, ограничение «один слот в день на тренера».

## Decision

Новый модуль с таблицей `trainings`, фиксированным названием и двухэтапным жизненным циклом слотов.

### 1. Таблица `trainings`

Миграция `a2b3c4d5e6f7_add_trainings` (revises `a1b2c3d4e5f6`):

| Поле | Тип | Ограничения | Описание |
|------|-----|-------------|----------|
| `id` | UUID | PK | |
| `center_id` | UUID | FK → centers.id | Центр |
| `coach_id` | UUID | FK → coaches.id, NULL | Выбранный тренер |
| `date` | DATE | NOT NULL | Дата тренировки |
| `start_time` | TIME | NOT NULL | Время начала |
| `location` | VARCHAR(500) | NOT NULL | Место проведения |
| `participants_count` | INTEGER | NULL | Фактическое количество участников, заполняется по факту явки (тренер/админ), 1–30 |
| `goal` | TEXT | NULL | Цель тренировки (тренер) |
| `status` | VARCHAR(20) | NOT NULL, `proposed` | `proposed` / `confirmed` / `cancelled` |
| `created_by` | UUID | FK → users.id | Кто создал слот |
| `plan_item_id` | UUID | FK → plan_items.id ON DELETE SET NULL | Связанный пункт плана |
| `created_at` / `updated_at` | TIMESTAMPTZ | NOT NULL, now() | |

Индекс `ix_trainings_center_date` на `(center_id, date)`.

### 2. Фиксированные константы

- `TRAINING_NAME = "Тренировка с сотрудниками РУСАЛа"` — единое название для пункта плана и подстановки в отчёт.
- `PLAN_CATEGORY = "4"` — пункт уходит в категорию 4 годового плана («Спортивные мероприятия на развитие ЦСЕ»).

### 3. API — `/api/v1/trainings`

| Метод | Путь | Роли | Семантика |
|-------|------|------|-----------|
| POST | `` | admin, director | Создать слот (`date`, `start_time`, `location`, `center_id?`) |
| GET | `` | coach, admin, director | Список (query: `center_id`, `date_from`, `date_to`, `status`, `coach_id`, `page`, `per_page` ≤ 200) |
| PATCH | `/{{id}}` | admin, director | Изменить слот (только `proposed`, иначе 422) |
| DELETE | `/{{id}}` | admin, director | Удалить слот (только `proposed`, иначе 422) |
| POST | `/{{id}}/select` | coach | Записаться: `{goal}` (кол-во участников укажет по факту явки) |
| POST | `/{{id}}/attendance` | coach, admin, director | Указать фактическую явку: `{participants_count: 1..30}`; только `confirmed` (иначе 422), coach — свою тренировку/свой центр (иначе 403); синхронизирует `plan_items.participants_count` |
| POST | `/{{id}}/cancel` | admin, director | Снять тренера: `confirmed` → `proposed` |

**Центр-скоуп:** coach → свой центр; admin → `user.center_id`; director/superadmin → из запроса.

**Ограничение** «один слот в день на тренера»: повторная запись на второй слот той же даты → 422.

### 4. Авто-создание пункта плана при подтверждении

`POST /{id}/select` (тренер записывается) дополнительно:

- Создаёт (при отсутствии) `EventPlan` на соответствующий год и `PlanItem` категории 4 с полями:
  - `name = TRAINING_NAME`, `date = "ДД.ММ.ГГГГ"`,
  - `quarter = (month − 1) // 3 + 1`, `participants_count = NULL` (заполнится по факту явки), `status = draft`;
- Связывает `trainings.plan_item_id` с созданным пунктом.

`POST /{id}/attendance` (тренер или админ проставляет явку) обновляет `trainings.participants_count` и синхронно пишет то же число строкой в связанный `plan_items.participants_count` — отчёт и план всегда видят актуальную явку.

`POST /{id}/cancel` (админ снимает тренера) удаляет связанный `PlanItem` и возвращает слот в `proposed`.

### 5. Подстановка в отчёт

Форма отчёта (`/reports/new`, п. 4 `sport_events`):

- При открытии загружаются **подтверждённые** тренировки текущего пользователя за отчётный период (`GET /trainings?status=confirmed&date_from&date_to`).
- Показывается хинт «Подтверждённые тренировки РУСАЛ за период» с кнопкой **«Заполнить из тренировок»** — она подставляет в textarea п. 4 строки вида `N. ДД.ММ.ГГГГ Тренировка с сотрудниками РУСАЛа (локация) — кол-во уч. — цель`.

### 6. UI

- Страница `/trainings` (sidebar, пункт «Тренировки»):
  - **coach:** секции «Доступные» (слоты `proposed` без тренера) + «Мои тренировки» (`confirmed`); «Записаться» → модалка только с `goal` + хинт «количество участников укажете по факту после тренировки»; на карточке confirmed — «Отметить явку» → AttendanceModal (число 1–30).
  - **admin/director: интерактивная сетка месяца** (заменяет карточный список). Сетка 6×7 (Пн–Вс), ячейки соседних месяцев приглушены, текущий день отмечен «Сегодня». В ячейке — чипы слотов по статусам:
    - `proposed` — outline-чип с временем (title: время · локация);
    - `confirmed` — primary-чип с временем и числом участников (title: время · тренер · N чел. · локация);
    - `cancelled` — приглушённый зачёркнутый.
    - Легенда статусов над сеткой; наведение на пустой день показывает подсказку «+ Слот».
  - **Интерактив админ/директор:**
    - клик по пустому дню → «Новая тренировка» с `date` pre-filled;
    - клик по чипу `proposed` → «Изменить» (дата/время/место pre-filled + кнопка «Удалить»);
    - клик по чипу `confirmed` → детальный модал (тренер, кол-во участников, цель) + «Явка: N чел. (изменить)» (админ тоже ставит/правит явку) + «Снять тренера» (PATCH confirmed запрещён бэкендом → 422, поэтому просмотр вынесен в отдельный модал);
    - «Снять тренера» и «Удалить» подтверждаются window.confirm.
- Месячная навигация, сортировка по дате/времени, бейджи статусов.

## Consequences

- **Положительные:** единый источник истины для тренировок РУСАЛ; пункт плана и отчёт заполняются автоматически, без ручного дублирования; ограничение «один слот в день» защищает от пересечения.
- **Отрицательные:** требуется связь с годовым планом (план может ещё не существовать — создаётся авто); если админ снимает тренера, уже сформированный текст в отчёте остаётся (генерируется заново кнопкой).

## Deferred

- Уведомления тренеру о новых доступных слотах.
- Ограничение количества слотов в месяц на центр.
