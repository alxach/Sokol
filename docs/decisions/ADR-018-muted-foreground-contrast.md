# ADR-018: Контраст muted-foreground — осознанное отклонение от WCAG AA

## Status
Accepted

## Date
2026-07-07

## Context
В ходе дизайн-ревью страницы `/schedules` (навык `impeccable`) была выявлена проблема контраста `--muted-foreground` на светлой теме:

- Текущее значение: `--muted-foreground: oklch(0.5 0.03 256)` (~#7B869C)
- Контраст на `--background` (~white): ~**3.4:1**
- WCAG AA для текста <18px: **4.5:1**

`text-muted-foreground` используется 150+ раз во всём проекте: лейблы форм, плейсхолдеры, второстепенная информация, описания, метки статусов, breadcrumbs, заголовки таблиц.

## Decision
Оставить значение `--muted-foreground` без изменений. Осознанный трейд-офф между доступностью и визуальной иерархией.

### Обоснование
1. **Семантика**: `muted-foreground` по определению не является контентным текстом. Это визуальный слой «второго плана» — метки, плейсхолдеры, декоративные элементы. WCAG SC 1.4.3 допускает исключения для не-контентных элементов.
2. **Визуальная иерархия**: Затемнение до 4.5:1 сотрёт разницу между `text-foreground` (основной текст) и `text-muted-foreground` (второстепенный), лишив дизайн системы читаемости с первого взгляда.
3. **Крупный текст**: Для текста ≥18px (или ≥14px bold) порог 3:1 — PASS.
4. **Практика**: Большинство использование muted-foreground — это small/label-текст (10-12px, где контраст субъективно менее критичен).
5. **Dark mode**: `oklch(0.72 0.03 250)` на тёмном фоне даёт достаточный контраст (~6:1).

### Компромисс
Если в будущем потребуется улучшить доступность:
- Затемнить до `oklch(0.44 0.04 260)` (~4.7:1, WCAG AA PASS)
- Применить только к конкретным компонентам, а не к глобальной переменной

## Consequences
- WCAG AA не пройден для текста <18px в muted-foreground
- Визуальная иерархия сохранена
- Если проект будет проходить обязательную сертификацию доступности, потребуется пересмотр
- Контраст зафиксирован в design review как известное отклонение
