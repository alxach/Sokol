# ADR-012: Coach Dashboard (Дашборд)

## Status
Accepted

## Date
2026-06-28

## Context

Дашборд (`/`) — главная страница приложения «СОКОЛ». Отображается всем ролям (admin, director, coach) с разным наполнением. Реализован на мок-данных, бэкенд не используется.

Текущая реализация (`frontend/src/routes/index.tsx`):

- **Для admin:** KPI-блок (4 карточки: спортсменов, медалей, соревнований, рейтинг), график медалей по месяцам (AreaChart), состав по дисциплинам (PieChart), топ-5 спортсменов по рейтингу, последние события, ближайшие старты
- **Для director:** сводка по центрам «Сокол» (3 карточки с городами, адресами, количеством спортсменов/тренеров/групп, эффективностью, медалями), затем те же блоки что у admin
- **Для coach:** приветственный баннер (ФИО, дисциплина, количество спортсменов, медалей, посещаемость), 4 KPI-карточки (мои спортсмены, занятия сегодня, всего медалей, средний рейтинг), список моих спортсменов (топ-5 по рейтингу), расписание на сегодня, последний план мероприятий со статусом, последние события

Данные фильтруются по `user.coachName` для coach, по `selectedCenterId` для director.

## Decision

Зафиксировать текущую архитектуру дашборда как целевую для мок-фазы. Изменения вносятся только при подключении реального API.

### Ролевая модель

| Роль | Приветствие | KPI | Спецблоки | Графики |
|------|-------------|-----|-----------|---------|
| Admin | Баннер «Сезон 2025/26» | Общие: спортсмены, медали, соревнования, рейтинг | — | Медали по месяцам, дисциплины, топ-5, события, старты |
| Director | Сводка центров (3 карточки) | Общие (те же что у admin) | Карточки центров: адрес, статистика, медали, эффективность | Медали по месяцам, дисциплины, топ-5, события, старты |
| Coach | Баннер: приветствие, ФИО, дисциплина, статистика | Персональные: мои спортсмены, занятия сегодня, медали, ср. рейтинг | Мои спортсмены (топ-5), расписание на сегодня, последний план | События |

### Модель данных (мок-фаза)

Данные приходят из `mock-data.ts`. Ключевые срезы для тренера:

- `myAthletes` — фильтр `athletes.filter(a => a.coach === coachName)`, сортировка по рейтингу
- `mySchedulesToday` — фильтр `schedules.filter(s => s.coachName === coachName && s.dayOfWeek === today)`
- `myAttendance` — записи посещаемости для `myAthletes`, вычисление процента `present / total`
- `myPlans` — фильтр `plans.filter(p => p.coachName === coachName)`, сортировка по дате создания
- `totalMedals` — сумма `a.medals.gold + a.medals.silver + a.medals.bronze` по `myAthletes`

Для admin/director:

- `topAthletes` — `athletes.sort((a,b) => b.rating - a.rating).slice(0, 5)`
- `monthlyResults` — готовые агрегированные данные из mock
- `disciplineMix` — распределение спортсменов по дисциплинам (массивы)
- `kpis` — статические показатели (1 284 спортсмена, 342 медали, 27 соревнований, рейтинг 1 728)
- `centerStats` — агрегация `centers` с вычислением городов и медалей

### Украшения (стилизация)

- Градиентный баннер (`var(--gradient-hero)`)
- 4 тона KPI-карточек: primary, accent, secondary, success
- Бейджи статусов с цветовыми схемами (success/green, destructive/red, primary/blue)
- Анимация загрузки: `animate-spin`

### Планируемая миграция на бэкенд

При подключении TanStack Query:
- `useQuery('dashboard/kpi')` — KPI по роли
- `useQuery('dashboard/coach-athletes')` — спортсмены тренера
- `useQuery('dashboard/coach-schedules')` — расписание на сегодня
- `useQuery('dashboard/centers')` — сводка центров
- Графики: `useQuery('dashboard/medal-trend')`, `useQuery('dashboard/discipline-mix')`

Бэкенд будет отдавать готовые агрегаты вместо фильтрации на фронтенде.

## Alternatives Considered

1. **Общий дашборд без ролевой фильтрации** — rejected. Admin, director, coach видят принципиально разную информацию. У тренера — своя статистика, у admin — общецентровая.
2. **Вынести кастомные блоки в отдельные компоненты** — отложено. Пока весь дашборд в одном файле, рефакторинг при подключении API.

## Consequences

- Файл `frontend/src/routes/index.tsx` (589 строк) содержит всю логику дашборда
- Ролевая фильтрация через `isCoach`, `isDirector`, `isAdmin` из `useAuth()`
- При добавлении бэкенда потребуется разделить на хуки (TanStack Query) и вынести графики в отдельные компоненты
- Coach-spec.md: раздел 2 (Дашборд) уже описан

## Notes

- В отличие от других модулей (соревнования, группы), дашборд остаётся в рамках мок-фазы — миграция на API планируется при интеграции всех модулей
- Блок «Последние события» (`recentActivity`) для coach не фильтруется по тренеру — отображаются все события системы. Это известное ограничение.
