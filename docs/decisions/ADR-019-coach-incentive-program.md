# ADR-019: Программа материального стимулирования тренеров (Положение ЦСиЗ)

## Status
Accepted

## Date
2026-07-14 (обновлено: редакция 8 от 09.07.2026)

## Context

В систему «СОКОЛ» интегрируется нормативная база программы материального (дополнительного) стимулирования и выплат материальной помощи тренерам, утверждённая приказом АНО «Центр Спорта и Здоровья» от 09.07.2026 № ЦСиЗ-26-П022 (редакция 8).

### Источники

- Текущий: `Положение о мат поддержке -ред. 8 от 09.07.2026.pdf`
- Архивный: `Положение о мат. поддержке -ред7 от 06.05.2026.pdf`

### Ключевые изменения ред. 8 (по сравнению с ред. 7)

1. **П. 1.3 (НОВЫЙ):** Выплаты осуществляются исключительно на усмотрение Организации, не носят систематического характера; являются правом, а не обязанностью Организации.
2. **Определение «Тренер» (Таблица 1, стр. 8):** Расширено — конкретизированы типы должностей (тренер-преподаватель, старший тренер-преподаватель и др.), типы договоров (трудовой / гражданско-правой), обязанность проводить занятия на территории ЦСЕ, требование придерживаться моральных принципов.
3. **Таблица 2 (Сокращения):** Добавлена строка СФП — Специальная физическая подготовка.
4. **П. 5.3 (расширен):** Благополучатель «формирует и направляет в адрес Организации обращение с указанием списка тренеров».
5. **П. 5.5 (НОВЫЙ — переписан):** Организация получает право запрашивать любую информацию у Благополучателя для проверки соответствия. Механизм оценки документов по «внутреннему убеждению». Возможность отказать в выплате и в дальнейшей поддержке при несоответствии/непредоставлении информации.
6. **Приложения №2-3 (реструктуризация):** Таблица критериев теперь содержит колонки: КРИТЕРИЙ | НОРМАТИВНОЕ ТРЕБОВАНИЕ | ФОРМА ПОДТВЕРЖДЕНИЯ. Конкретизированы нормативы (≥30/≥15 чел., ≥9/≥4,5 ч/нед) и формы подтверждения (журнал посещаемости — обязательно в отчёт; расписание — по запросу; фотоотчёт — обязательно в отчёт).
7. **Приложение №5 (детализация):** Подробные описания категорий мероприятий по разделам 3-5. Полный список категорий участников. Ограничения: лекции — не более половины за год; запрет на дублирование мероприятий двумя+ тренерами (исключение: >100 участников).
8. **Приложение №6 (пример заполнения):** Таблица выплат с расчётами НДФЛ/взносов и суммами «на руки» (Самбо: 50 000; Бокс: 25 000).

Документ определяет:
- Порядок выплат тренерам ЦСЕ (Центров спортивных единоборств), построенных при поддержке ОК «РУСАЛ»
- Выплаты носят **факультативный характер** (п. 1.3) — право, а не обязанность Организации
- Два уровня выплат: 50 000 руб. (полный) и 25 000 руб. (базовый)
- 5 критериев оценки работы тренера с указанием форм подтверждения
- Формы отчётности (ежемесячный отчёт тренера, протокол комиссии, план мероприятий)
- Требования к мероприятиям, категории участников и ограничения
- Процедуру согласования: тренер → Комиссия Благополучателя → Организация (АНО «Центр Спорта и Здоровья»)

### Список ЦСЕ (Приложение №1)

11 центров в городах: Ачинск, Братск, Волгоград, Дивногорск, Краснотурьинск, Красноярск, Саяногорск, Североуральск, Тайшет, Усть-Илимск, Шелехов.

## Decision

### 1. Маппинг критериев на модули системы

Пять критериев из Приложений №2-3 напрямую соответствуют полям отчёта тренера в модуле Reports (ADR-017). В ред. 8 каждому критерию добавлена колонка «Форма подтверждения»:

| № | Критерий | Норматив (50К / 25К) | Форма подтверждения | Поле отчёта | Модуль |
|---|----------|----------------------|---------------------|-------------|--------|
| 1 | Кол-во занимающихся на безвозмездной основе | ≥30 / ≥15 чел. в группе | Журнал посещаемости (**обязательно в отчёт**) | `athletes_count` | Reports |
| 2 | Кол-во часов занятий на безвозмездной основе | ≥9 / ≥4,5 ч/нед | Расписание (**по запросу**) | `hours_per_week` | Reports |
| 3 | Мероприятия с особыми категориями населения | ≥1 в месяц | Фотоотчёт с описанием (**обязательно в отчёт**) | `special_events` | Reports + Schedule |
| 4 | Соревнования/УТС/мастер-классы на территории ЦСЕ | ≥1 в месяц | Фотоотчёт + Положение/регламент/программа/списки участников (**обязательно в отчёт**; по запросу — документы) | `sport_events` | Reports + Schedule |
| 5 | Мероприятия по развитию спортсменов ЦСЕ | ≥1 в месяц со спортсменами | Фотоотчёт + текст лекции (**обязательно в отчёт**) | `development_events` | Reports |

**Важно:** Критерии 3-5 заменяемые — при невозможности проведения мероприятия из п.4 допускается второе мероприятие из п.3 (с указанием в п.4).

### 2. Модели данных

#### 2.1. Центр спортивных единоборств (CSECenter)

```typescript
interface CSECenter {

  name: string;           // "Центр спортивных единоборств г. Ачинска"
  city: string;
  address: string;

```

Источник: Приложение №1. 11 фиксированных центров. Используется для привязки групп, тренеров и отчётов.

#### 2.2. Программа поддержки / IncentiveProgram

```typescript
interface IncentiveProgram {
```

```typescript
// Добавить в существующий Report:
interface Report {
```

#### 2.5. План мероприятий тренера (CoachEventPlan)

Соответствует Приложению №7. Реальный формат подтверждён файлом `Флейшман Р.В план 1-3 кв.xlsx`.

Структура: план разбит по месяцам; внутри каждого месяца — мероприятия по категориям (разделы 3, 4, 5 из Приложения №5).

```typescript
interface CoachEventPlan {
  id: string;
  coachId: string;
  coachName: string;           // "Флейшман Роман Владимирович"
  sportType: string;           // "Дзюдо"
  year: number;
  months: PlanMonth[];
  status: "draft" | "submitted" | "approved" | "rejected";
  submittedAt?: string;
  approvedAt?: string;
}

interface PlanMonth {
  month: number;               // 1-12
  monthLabel: string;          // "Январь"
  isVacation: boolean;         // true = "отпуск"
  events: PlannedEvent[];
}

interface PlannedEvent {
  category: string;            // "3" | "4" | "5"
  categoryLabel: string;       // "Проведение мероприятий с определенными категориями населения"
  dateRaw: string;             // исходная дата из Excel: "2026-01-29", "19.02.2026,30.02.2026" или "4-20.02.2026"
  dates: string[];             // нормализованный массив дат (ISO) после парсинга
  name: string;                // Наименование мероприятия
  description: string;         // Формат/содержание/цель
  location: string;            // Место проведения
  participants: string;        // Категория участников (текстом)
  participantCountRaw: string; // исходное значение: "20-30", "15.", "112."
  participantCountMin: number; // минимальное число участников (парсинг)
  participantCountMax: number; // максимальное число участников (парсинг)
}
```

**Файл `Флейшман Р.В план 1-3 кв.xlsx` — разбор структуры:**
- Строка 1: заголовок
- Строка 2: колонки (7): Раздел отчёта | Дата | Наименование | Формат/содержание/цель | Место | Категория участников | Кол-во
- Строка 3: ФИО тренера, вид единоборств
- Далее: месяцы (Январь–Сентябрь), внутри каждого — строки мероприятий с категорией 3, 4 или 5
- Июль–Август: «отпуск», мероприятий нет
- Один месяц может содержать несколько мероприятий одной категории (например, Март: две лекции по категории 5)
- Категории 1 и 2 (кол-во занимающихся и часы) **не входят** в план — они берутся из посещаемости/расписания

**Выводы из анализа реального файла для реализации:**
- **Формат дат**: в реальных данных встречаются ISO (`2026-01-29`), через запятую (`19.02.2026, 30.02.2026`), диапазоном (`4-20.02.2026`), с лишними пробелами. Парсер должен быть tolerant к формату, но хранить в нормализованном виде (array of Date или startDate/endDate).
- **Валидация дат**: в файле найдена невалидная дата `30.02.2026` (февраль 2026 — 28 дней). Система должна предупреждать о таких ошибках при импорте/вводе.
- **Количество участников**: часто указывается диапазоном «20-30» или с точкой «20-30.» вместо целого числа. В модели `participantCount` стоит сделать string с возможностью парсинга, либо хранить `minParticipants`/`maxParticipants`.
- **Копипаста**: в сентябре обнаружена дата `15.02.2026` (явно перенесена из февраля). Нужен контроль актуальности дат при импорте.
- **Структура импорта**: при загрузке Excel-плана требуется маппинг колонок по позиции (а не по названию), т.к. названия колонок могут незначительно отличаться.

### 3. Категории мероприятий (Приложение №5)

Три раздела мероприятий, каждый со своими требованиями (детализация по ред. 8):

**Раздел 3** (special_events) — работа с населением:
- Зарядки и ОФП (групповые спортивные мероприятия)
- Весёлые/семейные старты, дни здоровья, забеги
- Работа со школами (уроки физкультуры, открытые уроки, мастер-классы, проект «Выбор сильных»)
- Экскурсии по ЦСЕ, дни открытых дверей
- Общегородские мероприятия с символикой ЦСЕ «Сокол» (флаги, футболки)
- Требования: безвозмездно, на территории ЦСЕ (вне ЦСЕ — только дошкольные/образовательные учреждения, детские дома, городские площадки с символикой)
- **Категории участников** (детализация ред. 8):
  - Лица до 18 лет, не занимающиеся в ЦСЕ (дошкольники, школьники, студенты СПО)
  - Родители (законные представители) спортсменов ЦСЕ
  - Старшее поколение (пенсионеры)
  - Лица с ОВЗ / инвалиды / дети без попечения
  - Несовершеннолетние в социально опасном положении («трудные» подростки)
  - Ветераны боевых действий и члены их семей
  - Работники предприятий РУСАЛ / Ен+ (корпоративный спорт)

**Раздел 4** (sport_events) — соревнования и сборы:
- Соревнования на территории ЦСЕ (турниры, ОФП/СФП с награждением)
- Летние УТС (выездные, ≥7 дней с проживанием; указываются один раз независимо от перехода между месяцами)
- Мастер-классы от чемпионов (звание ≥ МС, призёр ЧР/ПР/СССР)

**Раздел 5** (development_events) — развитие спортсменов:
- Лекции (не более половины за год; не допускается совместное проведение двумя+ тренерами)
- Встречи со спортсменами/тренерами
- Профориентационные беседы (МВД, МЧС, металлургики)
- Выездные экскурсии (пожарная часть, полиция, заводы)
- Семинары, тренинги, деловые игры (первая помощь, МЧС)
- Походы в театр/музей
- Социально-экологические и волонтёрские мероприятия

**Ограничения (обновлены в ред. 8):**
- Раздел 3-4: Одно мероприятие не могут указывать два тренера (исключение: крупные — >60 участников для 2 тренеров, >90 для 3 и т.д.). В крупных — каждый тренер указывает личный вклад.
- Раздел 5: Не допускается совместное проведение лекций, викторин, просмотров, демонстраций двумя+ тренерами. Для встреч/экскурсий — не более 2 тренеров (исключение: >100 участников).

### 4. Процесс выплаты (Business Flow)

```
Тренер
  │
  ├── Ежемесячно, до 5 числа → Отчёт (Report) → Комиссия
  │     └── Статусы: draft → submitted → approved/rejected
  │
  ├── Комиссия (≤4 рабочих дней) → Протокол (CommissionProtocol)
  │     └── Назначение/отказ в выплате
  │
  ├── Благополучатель (≤2 рабочих дней) → Заявка в Организацию
  │
  └── Организация (до конца месяца) → Перечисление средств
```

### 9. Новые регуляторные положения ред. 8

#### 9.1. Факультативность выплат (п. 1.3)

Выплаты осуществляются **исключительно на усмотрение Организации**, не носят систематического характера; являются правом, а не обязанностью Организации. Это ключевое изменение — в ред. 7 такой оговорки не было.

**Влияние на систему:** Добавлено поле `isDiscretionary: boolean` в `IncentiveProgram`. UI должен отображать дисклеймер о факультативности при отображении планов и отчётов.

#### 9.2. Расширенное определение «Тренер» (Таблица 1, стр. 8)

В ред. 7: «Тренер, тренер-преподаватель, тренер-преподаватель по спорту... имеющие договорные отношения с Благополучателями и занятия которых организованы на территории ЦСЕ»

В ред. 8:
1. Имеют отношения с Благополучателем, оформленные **по трудовому или гражданско-правовому договору**;
2. Организуют и проводят занятия **на территории объекта ЦСЕ**;
3. Придерживаются общепринятых моральных принципов: уважают честь и достоинство других, проявляют терпимость, действуют добросовестно и воздерживаются от поступков, наносящих вред благополучию окружающих.

**Влияние на систему:** В моделе `Coach` поле `contractType` может потребоваться для валидации допуска к программе.

#### 9.3. Механизм контроля Организации (п. 5.5)

Организация вправе:
- Запрашивать у Благополучателя **любую информацию** о исполнении Договора пожертвования
- Оценивать документы по своему «внутреннему убеждению» (всесторонний, полный, объективный анализ)
- **Отказать в выплате** за отчётный период при несоответствии/непредоставлении информации
- **Отказать в дальнейшей поддержке**

**Влияние на систему:** Модель `CommissionProtocol` должна поддерживать статусы «approved» / «rejected by Organization». Лог аудита запросов Организации (уже есть AuditLog).

#### 9.4. План мероприятий — срок предоставления (п. 6.5)

Благополучатель обязуется **не позднее чем за 10 рабочих дней до начала отчётного квартала** представить на согласование Организации план проведения мероприятий. План заполняется по Приложению №7.

**Влияние на систему:** В UI планов мероприятий добавить дедлайн: «за 10 рабочих дней до начала квартала». Автоматические напоминания.

#### 9.5. Пример расчёта выплаты (Приложение №6)

В ред. 8 добавлен пример заполнения таблицы выплат в протоколе комиссии:
- Самбо: начислено 74 827,24 → НДФЛ (13%) 7 471,00 → Взносы (30,2%) 17 356,24 → **на руки 50 000,00**
- Бокс: начислено 37 414,27 → НДФЛ 3 736,00 → Взносы 8 678,27 → **на руки 25 000,00**

**Влияние на систему:** Автоматический расчёт «gross» из «net»: `gross = net / (1 - NDFL_rate - Insurance_rate)`. Коэффициенты настраиваемые (ставка НДФЛ, ПФР, ФСС, ФФОМС, НС и ПЗ).

## Alternatives Considered

1. **Жёсткая кодировка 5 критериев** — принято (набор фиксирован регламентом). Нормативные значения (full/basic) хранимы в БД (`IncentiveCriteria`, на центр) и утверждаются руководителем центра/центров; слой отображения остаётся константным (2026-08-28).

2. **Хранить ЦСЕ в бэкенде vs. конфиге** — принято хранение в БД с seed-данными. Список может расширяться.

3. **Автоматический расчёт выплаты** — rejected. Окончательное решение принимает Комиссия. Система показывает сводку, но не назначает выплату.

4. **Факультативность выплат** — учтено через `isDiscretionary: boolean` в `IncentiveProgram`. Система не гарантирует выплату, а предоставляет инструменты расчёта и контроля.
